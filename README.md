# File Share

Минимальный self-hosted файлообменник: загрузил файл — получил короткую ссылку на скачивание.
Один файл на Python (только стандартная библиотека), без БД и внешних зависимостей.

## Возможности

- Загрузка файла (drag & drop или выбор) до **500 МБ**
- Уникальная ссылка вида `https://<host>/d/<token>` (публичная, без авторизации)
- Список загруженных файлов: размер, дата, владелец, копирование ссылки, удаление
- **Многопользовательская авторизация** (сессии в cookie, пароли — pbkdf2-sha256)
- **Права на пользователя**: загрузка / удаление / список всех файлов / список только своих
- **Админ-панель** (`/admin`): создание и удаление пользователей, их права и смена паролей
- Автоочистка: файлы хранятся **7 дней**
- Тёмный адаптивный интерфейс

## Запуск

### Локально

```bash
cp .env.example .env
python3 app.py
```

Откройте http://127.0.0.1:8081/.

### Docker

```bash
docker compose up -d --build
```

### Переменные окружения

| Переменная | По умолчанию | Описание |
|---|---|---|
| `HOST` | `0.0.0.0` | адрес прослушивания |
| `PORT` | `8081` | порт |
| `UPLOAD_DIR` | `/data` | каталог для файлов и `.meta.json` |
| `AUTH_USER` | `admin` | логин стартового администратора (создаётся при первом запуске) |
| `AUTH_PASSWORD` | _(пусто)_ | пароль стартового администратора; пусто -> `admin` |

Пользователи хранятся в `<UPLOAD_DIR>/.users.json` (создаётся автоматически), владельцы
файлов и метаданные — в `<UPLOAD_DIR>/.meta.json`.

## Авторизация и права

Вход — на странице `/login` (сессия в HttpOnly-cookie, TTL 7 дней). Загрузка, список и
удаление требуют входа. Скачивание по ссылке `/d/<token>` остаётся **публичным**, чтобы
получатель мог открыть ссылку без пароля.

Права пользователя (задаются администратором в `/admin`):

| Право | Что даёт |
|---|---|
| `upload` | загружать файлы |
| `delete` | удалять файлы (свои; чужие — только при праве «список всех») |
| `view_all` | видеть в списке файлы всех пользователей |
| `view_own` | видеть в списке только свои файлы |

Стартовый администратор (`AUTH_USER`) имеет все права и доступ к `/admin`; создавать
других администраторов нельзя. Пользователи могут видеть только то, что позволяют права.

Проверка:

```bash
curl -i http://127.0.0.1:8081/                 # 303 -> /login
curl -i -c jar -d 'username=admin&password=...' http://127.0.0.1:8081/login
curl -b jar http://127.0.0.1:8081/api/files
```

За обратным прокси `HOST` зависит от того, где стоит прокси:

- прокси на **том же** хосте — `HOST=127.0.0.1` (сервис не торчит в сеть);
- прокси на **другом** хосте (как в проде: Caddy на CT 108, приложение на zoopark) —
  `HOST=0.0.0.0` или LAN-IP хоста, иначе прокси получит `connection refused`.

## HTTP API

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/login` | страница входа |
| `POST` | `/login` | вход (form: `username`, `password`) |
| `GET` | `/logout` | выход (сброс сессии) |
| `GET` | `/` | страница загрузки и список файлов (нужен вход) |
| `POST` | `/upload` | загрузка файла (multipart/form-data, поле `file`; право `upload`) |
| `GET` | `/api/files` | список файлов пользователя (JSON) |
| `GET` | `/d/<token>` | скачивание файла (**публично**) |
| `DELETE` | `/api/delete/<token>` | удаление файла (право `delete`) |
| `GET` | `/admin` | админ-панель (только администратор) |
| `POST` | `/admin/users` | создать пользователя |
| `POST` | `/admin/users/<name>` | изменить права/пароль пользователя |
| `POST` | `/admin/users/<name>/delete` | удалить пользователя |

## Деплой (zoopark)

Сервис хостится на zoopark (192.168.0.217) под systemd, публикуется через Caddy на
`files.ivanwebdeveloper.ru` (CT 108):

```bash
sudo mkdir -p /opt/file-share && sudo chown bvv:bvv /opt/file-share
rsync -a --exclude .git --exclude data ./ bvv@192.168.0.217:/opt/file-share/
# /opt/file-share/.env: HOST=0.0.0.0, PORT=8081, UPLOAD_DIR=/opt/file-share/data, AUTH_USER=..., AUTH_PASSWORD=...
ssh bvv@192.168.0.217 'sudo systemctl enable --now file-share'
```
